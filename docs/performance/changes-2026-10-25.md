# Performance changes: review report (25 October 2026)

Everything changed on the `perf/improvements` branch, why, what it measured, and how the look was checked. The starting point is [baseline-2026-10-25.md](baseline-2026-10-25.md), measured on `main` at `f1f5759`.

## Summary

The two problems reported:
- **Grid scroll jitter (desktop): fixed.** The biggest cause was a ~0.9 s freeze when the footer's 3D controller loaded mid-grid. Next came card hover effects starting on cards that slid under the pointer.
- **Dialog open/close jank (desktop): much smoother.** The main causes were a full-page backdrop blur re-rendered under the flying panel, the page re-laying out a scrollbar's width wider on every open and close, and whole-page re-renders and restyles on each open and close.

Final comparison, `main` against this branch, interleaved in one session on the same machine (Intel Iris Xe, 1440×900):

| Measure | `main` | This branch |
|---|---|---|
| Grid scroll: frames over budget | 4.3–5.9% | **0.3–0.6%** |
| Grid scroll: worst frame | 450–533 ms | **83–117 ms** |
| Grid scroll: scroll-step jumps (visible jitter) | 9–10 | 2–8 |
| Dialog, first open: slow frames | 11–14 | **5–6** |
| Dialog: click handler before the animation starts | 51–70 ms | **27–41 ms** |
| Dialog: grid cards resized behind the overlay | yes (275.6 → 278.4 px) | **no** |
| Idle at the top of the page: main thread busy | 18% | **8–10%** |
| Lighthouse accessibility, /deals | 96 | **100** |
| Lighthouse SEO, home and /deals | 91–92 | **100** |

**Why the numbers vary between runs.** The machine's background load (other apps) changed over the day, and absolute numbers move with it. The baseline was taken under heavier load: grid 27–29% over budget, dialog opens with 21–31 slow frames. Each step below was measured under the load at the time, so compare within a row, not across sections.

## Changes, by commit

### Grid scroll

**`f1d0695` Draw the footer's 3D controller in a worker**
- *Problem.* Building the scene blocked the page: 593 ms creating the WebGL context, then 1.3 s linking shaders. It happened mid-grid, because loading starts when the footer is within 1.5 screens.
- *Change.* Where the browser supports WebGL on an OffscreenCanvas, the scene builds and draws in a worker. The page only posts sizes and sequence positions. The worker draws the latest of each once per frame, so a slow GPU never falls behind the scroll.
- *Fallback.* Other browsers keep drawing on the page. If the worker fails, a fresh canvas takes over on the page.
- *Other.* The cube map now loads through `createImageBitmap`, which also works in a worker. The model has no embedded textures, so loading it in a worker works in Safari too.
- *Files.* New `lib/controller-worker.ts` and `lib/controller-host.ts`; `lib/controller-scene.ts` takes sizes as arguments and no longer reads `window` or the DOM; `components/motion/footer-controller.tsx` creates its canvas in the effect, so it survives StrictMode's double mount.
- *Measured.* Grid worst frame 917–967 → 167–201 ms. Both main-thread tasks are gone.
- *Look.* Controller screenshots mid-sequence and at rest match the old ones: at most 8/255 per pixel, the film grain's own noise.

**`4cf5d6b` Build the 3D scene once the page is still**
- *Problem.* Even in a worker, the GPU process compiling shaders held up the page's frames: hitches of ~200 ms.
- *Change.* The model and cube map still load at once. The GPU work waits until the page hasn't scrolled for 250 ms.
- *Measured.* Grid worst frame 167–217 → 50–67 ms. With the 3D load blocked entirely, the worst frame was 67 ms, so the controller no longer adds anything.

**`1ed321f` Hold card hover effects for the whole of a scroll glide**
- *Problem.* Cards ignored the pointer only above 4 px per frame, and every Lenis glide ends slower than that. 22–27 cards per run started their hover mid-scroll.
- *Change.* `<html>` carries `scrolling` for the whole glide (class renamed from `scrolling-fast`). It only changes when the state changes.
- *Behaviour change (approved).* Hover now starts when the glide stops, not during its slow tail.
- *Measured.* Frames over budget ~20% → 8.1%; p95 50 → 33 ms.

**`c70ddbe` Card hover moves and fades instead of re-laying out**
- *Problem.* The "View N offers" row grew through a `grid-template-rows` transition, which runs layout every frame for 500 ms. The neon glow transitioned `box-shadow`, which is repainted every frame.
- *Change.* The row is always laid out below the card's edge, and the text block slides up 24 px to reveal it. The glow is drawn once on its own layer and fades in. The tilting card's `overflow-hidden` moved to an inner wrapper so the glow can show outside it.
- *Measured.* Pointer sweep across a row: layout 288 → 45 ms, layout passes 610 → 142, slow frames 0.7% → 0.25%.
- *Look.* Screenshots of a card at rest and fully hovered match the old ones within run-to-run noise. The row sits at the same height (the block moves the same 28 px).

### Dialog open and close

**`41e4b9e` Blur the page behind a dialog once its panel has landed**
- *Problem.* The overlay faded in with its 8 px backdrop blur while the panel flew over it, so the GPU re-blurred the whole page every frame. The invisible dialog was also still drawing its own 37.5 px blur.
- *Change.* The overlay fades in unblurred during the flight, and the blur eases in after landing. The dialog is `invisible`, not just transparent, until then.
- *Unchanged.* Without a flight (a shared link), nothing changes, and other dialogs keep their blur.
- *Behaviour change (approved).* The background blur arrives after the panel lands.
- *Measured.* Slow frames per open 21–31 → 4–11; typical frame 33 → 16.7 ms.

**`fdf9ac2` Keep the page's width while a dialog is open**
- *Problem.* Stopped Lenis set `overflow: clip` on `<html>`. That removed the scrollbar before Radix's scroll lock could measure it, so nothing took its place. The page re-laid out 14 px wider under every dialog, each grid card resized, and it reversed on close. A closing panel also aimed at the card's widened position and snapped at the end.
- *Change.* A CSS override (`index.css`) leaves the overflow alone. Radix's lock then hides the scrollbar and keeps its width as a margin, as it's built to. The fixed header opts in with `width-before-scroll-bar`.
- *Measured.* Card and header widths stay constant. Open worst frame 117–183 → 67–83 ms.

**`cce7007` Opening or closing a game re-renders the dialog, not the page**
- *Problem.* `?game` was part of the URL state the whole `App` read, so opening a game re-rendered the entire page inside the click handler, and closing did the same in `popstate`.
- *Change.* A new `useGameId()` subscription feeds a small `GameDialogHost`. The rest of the page reads a view of the URL that stays the same while only the game changes.
- *Sound.* Dialog whooshes moved to `useDialogSound(id, open)`, which tracks open dialogs across components. There's still one whoosh as the first dialog opens and one as the last closes, and going from a game straight to the cart is still silent.
- *Measured.* Close handler 73–132 → 46–80 ms.

**`b7450e9` Mount the dialog's body once, holding its entrance until the panel lands**
- *Problem.* The body was mounted twice per flight: once hidden, so the panel could measure it, then again in the landing frame.
- *Change.* It is mounted once. Its entrance (cover wipe, title, offers) waits on a `play` flag, the pattern the hero already uses. `SplitText` and `CompareView` gained an optional `play` prop.
- *Look.* The settled dialog matches the old one. The only differences are in the blurred background, which no longer shifts, and the glow pulse's timing.

**`4898892` Stop Radix's scroll lock from restyling the whole page**
- *Problem.* Radix sets the CSS variable `--removed-body-scroll-bar-size` on `<body>` on open and removes it on close. Custom properties are inherited, so each change recalculated the style of every element on the page: ~35 ms, twice per dialog.
- *Change.* Registered with `@property` as non-inherited. Nothing in the app reads it.
- *Measured.* The same change costs 1.3 ms instead of 34.8 ms. The forced style recalc on open fell from 1,182 elements to 16.

### Work done while the page is idle

**`ffe5af8` Slide the hazard band with a transform, and rest it off screen**
- *Problem.* `background-position` animation is restyled and repainted on the main thread every frame, and it ran even off screen.
- *Change.* A strip one stripe period wider slides by that period with a transform, which the GPU runs on its own. An IntersectionObserver pauses it off screen.
- *Look.* At the same phase the stripes match, except for edge anti-aliasing (0.8% of pixels, max 39/255).

**`a90075c` Step Lenis only while it has a glide to play**
- *Problem.* Lenis was stepped from a keep-alive frame callback, so the page requested every frame even when nothing moved.
- *Change.* The loop starts on wheel input (Lenis's `virtual-scroll` event) or a programmatic scroll (`useScrollTo`) and stops a couple of frames after the glide ends. Lenis's clock is reset on each start, so the first step doesn't cover the whole pause.
- *Behaviour.* Checked against the old build: the same glide (34 vs 35 small steps per notch), no jump after an idle pause, and "Start browsing" reaches the same target.

**`236a9e9` Rest the header's equalizer while the header is tucked away**
- The five bars animated forever, a restyle every frame, including while the header was hidden on scroll-down.
- *Measured (with the two commits above).* Idle main-thread use 18% → 8–10%. While you're in the grid, only the grain still animates; before, the five bars and the off-screen hazard band did too.

### Touch screens

**`bf0f1a3` Lighter effects on touch screens**
- *What's new.* A new `touch:` Tailwind variant and `useFinePointer()` hook, both on the query `(hover: none), (pointer: coarse)`.
- *On a touch screen:*
  - no film grain
  - no scroll-linked blur on the hero title (the scale and fade stay)
  - a lighter hero glow (48 px instead of 120 px)
  - no card tilt or glare, which never fire without a mouse anyway
- *Desktop.* Unchanged: hovered-card screenshots match within grain noise.
- *Checked.* Under DevTools-style touch emulation, every effect switches as intended.
- *Not yet measured.* See the open items: the gain still needs measuring on a real phone.

### Load time and audits

**`5265dc0` Render the cards, hero art and deals in slices as their data lands**
- The grid, the hero's covers and the deals lists follow their data through `useDeferredValue`, so React renders them in slices it can pause between frames instead of one long task.
- *Measured.* Small: /deals median Total Blocking Time 128 → 90 ms. The home page is within noise.

**`5e0d13e` Accessible split-text headings; add robots.txt**
- *Headings.* `SplitText` put `aria-label` on a plain `span`, which isn't allowed on an element without a role. The text is now in a visually hidden span, and every visual part is `aria-hidden`. The headings look the same.
- *robots.txt.* It allows everything, as having none did. The single-page-app fallback no longer answers it with `index.html`.
- *Result.* Home and /deals score 100 for accessibility, best practices and SEO.

## Tried and dropped

| Plan item | Outcome |
|---|---|
| Stage the 3D load across idle callbacks | Replaced by the worker. Profiling showed the freeze was context creation and shader linking, which can't be split up on the page. |
| Use the WooCommerce 300 px `thumbnail` for covers | **Deferred.** The thumbnail is a square crop and would look soft on 2× screens. The right fix is to carry each image's `srcset`, which the feeds do include, through the pipeline (adapter → database → shared types → `CoverArt`), and that is a bigger change. Venture Games, the largest group of oversized covers (800 px), has no resized copies at all. |
| Render grid rows outside the scroll event (`useFlushSync: false`) | Reverted. No gain on desktop, and inconsistent on the mobile profile. |
| Transform-based flying panel | Not done. After the blur, scrollbar and re-render fixes, the panel's own animation was no longer a measurable bottleneck. Doing it would also need per-frame correction of the image and corner radius under scale. |
| Freeze the panel's target box mid-flight | Not done. Retargeting turned out not to be a cost; the render behind it was, and that is fixed. |
| Mount the dialog (closed) at idle | Reverted. The first open measured worse (13–18 slow frames vs 9–14). |
| Static loading-screen shell in `index.html` | Not done. Text styled before the fonts load would visibly swap. The mobile LCP is mostly the loading screen's own pacing: START appears once the bar fills, the data arrives and the cover art loads. |

## Open items

1. **The mobile improvement is unverified.** On the 4× CPU-slowed phone profile, run-to-run noise on this machine (the same build measured 39.6 and 23.3 fps in two runs) was bigger than any difference between builds. The phone-specific savings (grain, blur) are on the GPU side, and the profile doesn't slow the GPU. Measuring on a real phone (Chrome remote debugging, Performance panel) is the next step.
2. **The grid on a slow phone is still main-thread bound.** It renders new rows of cards, each with about 10 motion values and springs. A lighter card for touch screens (no springs, CSS-only entrance) is the likely next lever.
3. **A remaining whole-page restyle when a dialog opens.** It happens when Radix moves focus into the dialog (~1,150 elements, 26–82 ms depending on load). Invalidation tracking found no single trigger left.
4. **Cover image sizes.** See the deferred item above.
5. **Lighthouse home LCP is unchanged.** On `main` and this branch alike it is the loading screen's START label, decided by the loading sequence, not rendering speed.
6. **Pre-existing, untouched:**
   - a `label-content-name-mismatch` advisory on the header's logo button (`aria-label="LootLedger, home"`)
   - lint warnings: `only-export-components`, and `set-state-in-effect` in `game-dialog.tsx`

## How to review

**Automated checks**, all passing:
- `pnpm -r typecheck`
- `pnpm test` (202 tests)
- `pnpm --filter @lootledger/web lint` (no errors)

**Manual checks in a browser**, against `pnpm --filter @lootledger/web build && pnpm --filter @lootledger/web preview`:

1. Scroll the grid with a mouse wheel while the pointer rests on the cards. Cards shouldn't light up mid-glide, and should hover normally once it stops.
2. Scroll on toward the footer. There should be no hitch as the 3D controller loads, and it should play and settle as before.
3. Open a card. The panel should fly smoothly, the background blur should ease in after it lands, and nothing should shift behind the overlay. Close it, and the panel should land exactly on the card.
4. Open a game, then "Add to cart" → open the cart. There should be one whoosh, not two.
5. Use "Start browsing", the deals section links and "Back to top". Each should glide to its target.
6. In DevTools device mode (a phone), there should be no grain, no title blur on scroll, and a softer glow.
7. With the OS "reduce motion" setting on, Lenis is off, and the controller should show at rest.

**Re-measuring.** The scripts are in [`bench/`](bench/) and run as described in the baseline report. Changes since then:
- the scripts take `URL`
- `grid-bench` counts frames with a blank row at the bottom of the screen
- `scroll-bench`'s mobile profile emulates a touch screen (`hasTouch`)
- `hover-bench.cjs` sweeps the pointer across a row of cards
- `pngdiff.cjs` diffs two screenshots within a box
